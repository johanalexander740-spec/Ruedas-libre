RUEDA LIBRE v1.0
Bitacora del proyecto

RESUMEN
Sitio informativo en tres paginas: inicio, tarifas y rutas, y reservas.
Se usa HTML para estructura y contenido, CSS para presentacion adaptable y
estados de interaccion. No se necesita JavaScript para las funciones incluidas.
El formulario aplica validacion nativa del navegador; para recibir y guardar
reservas hace falta conectar un servidor o servicio de formularios.

HTML, CSS Y PETICION AL SERVIDOR
El navegador solicita el documento HTML con una peticion GET. Al leerlo solicita
la hoja CSS y las imagenes mediante otras peticiones GET; las fuentes se cargan
desde Google Fonts. HTML define contenido, enlaces, tablas, formulario y
semantica. CSS define color, tipografia, distribucion, adaptacion y foco.
JavaScript no se usa en esta version. El formulario declara POST y comprueba
campos en el navegador, pero una web estatica no procesa el envio: se necesita
configurar un servicio de reservas antes de recibir solicitudes reales.

ELECCIONES DEL FORMULARIO
Correo usa type=email para comprobar el formato. Fecha usa type=date y limites
minimo y maximo para evitar fechas fuera del periodo. Documento y celular usan
pattern para comprobar digitos y longitud; bicicleta usa radio para permitir
una sola opcion. Los campos tienen etiquetas asociadas y nombres de envio.

CSS, ESPECIFICIDAD Y MODELO DE CAJA
La hoja externa css/styles.css usa variables de marca, Montserrat y Open Sans,
escala de espacios, estilos compartidos, tarjetas, tablas y formulario.
El conflicto original era #menu a (especificidad 1,0,1) frente a .activo
(0,1,0): el selector con ID prevalece. Se resolvio usando selectores del menu
que consideran el estado activo, sin !important.
Todos los elementos usan box-sizing: border-box. No se registran mediciones de
DevTools en esta bitacora; el ancho de las tarjetas depende del viewport y de
la distribucion adaptable.

ESTADO DE ENTREGA
Las nueve rutas de navegacion entre paginas se comprobaron en local; las tres
paginas cargan con un main, las imagenes locales existen y las validaciones
principales fueron probadas en el navegador. No se comprobaron aun cambios en
DevTools ni una URL de GitHub Pages. El envio real de reservas queda pendiente
de conectar un servicio backend. Publicar y cambiar la descripcion del
repositorio requiere acceso a GitHub.
